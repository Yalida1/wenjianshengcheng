一、业务目标

本轮页面用于把系统生成的招标文件草稿，
转换为经过人工审校的正式定稿文件。

完整流程：

招标文件 V0.1 草稿
→ 分章节审阅
→ 修改动态内容
→ 查看字段和来源证据
→ 处理校验问题
→ 必要时使用 AI 辅助修改
→ 与内部历史版本或客户历史人工稿对比
→ 运行最终校验
→ 定稿为 V1.0
→ 导出 DOCX/PDF。

页面必须明确体现：

1. 生成完成不等于定稿完成；
2. 固定模板条款与动态生成内容必须明确区分；
3. 已确认的金额、期限、主体和范围不能在正文中被随意改写；
4. 修改确定性字段时，需要返回字段确认或使用字段修改流程；
5. AI 修改必须展示修改前后差异，用户确认后才能应用；
6. AI 不得直接修改金额、日期、主体、数量、付款或其他关键字段；
7. 所有文档问题必须定位到具体章节或段落；
8. P0 阻断问题未清零时不能定稿；
9. 来源可研或模板有新版本时不能静默覆盖当前文档；
10. 定稿版本不可直接覆盖，只能创建后续修订版本；
11. 导出文件必须记录来源版本、字段快照和模板版本；
12. 招标文件定稿后才能作为合同阶段的上游文件。

   → 定位文档章节。

   → 打开段落来源抽屉。

   → 打开 AI 辅助修改。

   → 展示前后差异
   → 用户确认
   → 应用正文。

   → 打开校验抽屉。

8. 点击定位
   → 滚动到具体问题段落。

   → W09 校验中心。

    → 定稿按钮禁用。

    → 校验通过
    → 进入定稿。

    → 解析
    → 展示差异。

14. 保存时发生并发冲突
    → 打开版本冲突对话框。

15. 来源可研出现新版本
    → 显示来源变化提示，
    不自动覆盖。

16. 模板发布新版本
    → 显示模板变化提示，
    不自动混用。

17. 最终校验通过
    → 点击定稿
    → 定稿确认对话框。

    → 文档 V1.0

    → 导出对话框

    → 导出完成。

    → 合同输入来源占位页。
