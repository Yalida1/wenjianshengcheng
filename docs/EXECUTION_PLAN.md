# 项目文件链式生成平台执行计划

## 目标

在保留现有 Figma 原型主要视觉风格和业务布局的前提下，将仓库建设为可部署、可测试、可审计的项目文件链式生成平台。唯一业务主链路为项目建议书、可行性研究报告、招标文件、合同。

## 交付原则

1. 真实业务数据必须来自上传文件、系统权威值或人工确认。AI 建议不直接成为正式值。
2. P0 字段在缺失、冲突、无效、仅供参考、AI 建议或未经确认的提取状态下阻断定稿。
3. 上游文件或模板变更只标记下游过期，不覆盖已经定稿的版本。
4. 已定稿版本保持不可变，后续修改必须创建新修订草稿。
5. 客户模板优先。仓库内置模板仅标记为 Demo 通用模板。
6. 自动化测试使用确定性 Demo Provider，不依赖付费模型。

## 实施顺序

### 第一阶段 基础平台

- 建立 FastAPI、SQLAlchemy、Alembic、PostgreSQL、Redis、Celery、MinIO 工程。
- 建立组织、用户、角色、权限、项目成员和对象级访问控制。
- 建立登录、退出、会话续期、密码安全存储、账号停用和审计日志。
- 建立统一错误格式、请求标识、分页、revision 并发控制。

### 第二阶段 文件和字段

- 实现 DOCX、PDF、XLSX、PNG、JPG、JPEG 上传与安全校验。
- 实现对象存储、版本、SHA256、解析任务、重试和 OCR 待处理状态。
- 实现文档块、字段定义、字段值、证据和确认记录。
- 实现 P0 门禁及禁止映射规则。

### 第三阶段 模板和生成

- 实现模板上传、解析、版本、发布、停用和适用范围筛选。
- 实现版本化提示词、Provider 抽象和结构化输出校验。
- 实现可重试、可取消、可恢复的分章节生成任务。
- 实现文档版本、章节、内容块、自动保存和并发冲突。

### 第四阶段 校验和导出

- 实现结构、字段、金额、付款、日期、范围、变量、格式和来源校验。
- 实现定稿门禁、不可变正式版本和新修订草稿。
- 实现 DOCX、PDF、XLSX 导出和可追溯元数据。
- 生成并验证 Demo Golden Case。

### 第五阶段 前端和交付

- 使用 React Router 替换 Hash/Page 联合状态。
- 使用 TanStack Query、React Hook Form、Zod 和 OpenAPI 生成客户端。
- 接通加载、失败、空、403、409、草稿恢复和异步任务状态。
- 补齐 Vitest、RTL、Playwright、pytest、容器集成、安全和密钥扫描。
- 运行 `make verify`，记录真实命令、时间、退出码和结果。

## 验收边界

生产模型密钥、客户正式模板、客户历史样本、授权字体、外部系统账号、生产域名和证书不在仓库内伪造。缺少这些材料时，平台仍须使用明确标记的 Demo Provider、Demo 模板和 Demo Golden Case 完成自动化验证。
