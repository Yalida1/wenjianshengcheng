# 内置模板文档生成专项验收执行计划

## 1. 目标

验证全部内置模板的登记、正式源、预检、字段快照、生成任务、人工审阅、校验、定稿、导出、追溯和权限门禁。验收输出必须来自平台真实 API、数据库、异步任务、对象存储和 DOCX/PDF 导出链路。

## 2. 隔离边界

- Compose 项目：`project-document-chain-builtin-acceptance`
- Web 端口：`18080`，不占用日常环境的 `8080`
- PostgreSQL 数据库：`builtin_template_acceptance`
- Redis 命名空间：`11`
- S3 桶：`project-documents-builtin-template-acceptance`
- 组织：`内置模板专项验收组织`
- LLM：`demo/deterministic-v1`，只验证真实 provider 接口与任务链，不调用客户 DeepSeek 额度

## 3. 执行顺序

1. 新建隔离基础设施，执行数据库迁移与种子初始化。
2. 通过 API 登录并建立五类角色用户、固定验收项目和上游文件。
3. 同时从 API、数据库和对象存储盘点全部内置模板。
4. 逐一验证国家正式文本索引不可生成；逐一生成所有可生成内置模板的最小 DOCX。
5. 按项目建议书、可研报告、招标文件、合同四阶段完成正向主链路。
6. 先导出合同签署前草稿，再补齐主体、价税、付款等字段并形成待签署版。
7. 执行阻断映射、P0、付款、占位符、模板有效期、固定条款、上游变更、不可变版本和只读权限负向用例。
8. 校验 DOCX OOXML、LibreOffice 打开/转换、PDF 页面与可提取文本，渲染关键页 PNG 并人工查看。
9. 生成字段追溯表、血缘、格式、模板保真、完整性和汇总报告。
10. 执行浏览器 E2E 和专项门禁汇总；任一关键项失败时命令非零退出。

## 4. 通过标准

- 全部 22 份内置记录可盘点：9 份国家正式文本索引、9 份正式大纲适配模板、4 份平台参考模板。
- 9 份索引只能查阅来源，不得进入生成任务；13 份可生成模板均完成真实最小生成和 DOCX 导出。
- 固定数据四阶段文件均由平台链路生成；金额、范围和期限不发生禁止映射。
- 12 类负向门禁返回预期 HTTP 状态、错误码，且数据库和审计状态可核对。
- DOCX/PDF 完整性、格式和模板保真报告没有阻断项。
- 浏览器 E2E 通过；最终 `acceptance-summary.json` 的 `overall_status` 为 `passed`。

## 5. 失败处理

失败时保留隔离环境与完整日志，修复真实缺陷后重跑失败用例及全量专项验收；不得修改预期值或降低 P0、权限、模板有效期、固定条款、不可变版本门禁。
